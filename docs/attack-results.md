# Attack suite results

Generated by `npm run attacks` on 2026-10-25 against PostgreSQL 17.11 in Docker.
Attacker: user `alice` (`app.user_id = 'alice'`), role `ai_reader`, timeout 2000 ms, row cap 500.
A result is a **leak** if it contains any secret marker (Bob's rows, password hashes, API keys), a **write** if any table, row, or function changed, **slow** if it ran longer than the timeout + 2.5 s.

| | Attacks | Safe | Leaks / writes / slow |

| **pg-guard-sql (all layers)** | 75 | **75/75** (67 blocked by the validator, 7 ran but contained, 1 stopped by Postgres) | 0 |
| Database layers only (validator removed) | 75 | 71/75 | 4 |

Without the validator, these got through the database layers, which is why the parser allowlist exists:

- #5 Switch RLS user, then read: **LEAK** (26 rows incl. foreign data)

- #56 SECURITY DEFINER function in SELECT list: **LEAK** (2 rows incl. foreign data)
